# Test Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a real, logged-in user flip into an isolated demo world (same commodities, same other users as counterparties) where every transaction, balance and notification they create is invisible to production and to every other non-test view.

**Architecture:** A second Postgres schema `test_mode` lives in the same database as `public`. A Django database alias `test_mode` points at the same connection with `search_path=test_mode,public`. A `DATABASE_ROUTERS` router sends four models (`Transaction`, `Balance`, `Notification`, `NotificationSettings`, plus their `simple_history` counterparts) to that alias, only while a request-scoped flag is set. The flag is set by a middleware that recognizes the `/api/v1/test/` URL prefix — the exact same views and services run in both modes, unmodified. Everything else (`User`, `Commodity`, `HarvestSeason`, `ConversionRecipe`, admin, analytics) always resolves to `public`, so the test world always sees the live catalog and the live user list without copying any of it.

**Tech Stack:** Django 5 multi-database routing (`DATABASE_ROUTERS`, `contextvars`), Postgres schemas, pytest-django multi-db tests.

**Spec:** none — this plan carries its own design (see Architecture above and the per-task rationale). Ticket: WA-679.

## Global Constraints

- No new package dependencies.
- Auth (`/auth/...`) is never mounted under `/api/v1/test/` — login always happens against `public`.
- Nothing outside `Transaction`, `Balance`, `Notification`, `NotificationSettings` (and their `historical*` twins) may be routed to `test_mode`. Every other model always resolves to `default`.
- No real push, SMS or email may leave the system as a side effect of a request made under `/api/v1/test/`.
- Match existing code style: `@dataclass(slots=True)` services, `@staticmethod` methods, full type hints, `pytestmark = [pytest.mark.django_db]` at module level for DB tests.

```python
# whimo/common/test_mode.py
from collections.abc import Iterator
from contextlib import contextmanager
from contextvars import ContextVar

_test_mode: ContextVar[bool] = ContextVar("test_mode", default=False)


def is_test_mode() -> bool:
    return _test_mode.get()


@contextmanager
def enable_test_mode() -> Iterator[None]:
    token = _test_mode.set(True)
    try:
        yield
    finally:
        _test_mode.reset(token)
```

```python
# whimo/common/middleware.py
from collections.abc import Callable

from django.http import HttpRequest, HttpResponse

from whimo.common.test_mode import enable_test_mode

TEST_MODE_PREFIX = "/api/v1/test/"


class TestModeMiddleware:
    def __init__(self, get_response: Callable[[HttpRequest], HttpResponse]) -> None:
        self.get_response = get_response

    def __call__(self, request: HttpRequest) -> HttpResponse:
        if not request.path.startswith(TEST_MODE_PREFIX):
            return self.get_response(request)

        with enable_test_mode():
            return self.get_response(request)
```

```python
# whimo/common/db_router.py
from typing import Any

from whimo.common.test_mode import is_test_mode

TEST_MODE_MODEL_NAMES = {
    "transaction",
    "historicaltransaction",
    "balance",
    "historicalbalance",
    "notification",
    "historicalnotification",
    "notificationsettings",
    "historicalnotificationsettings",
}


class TestModeRouter:
    def db_for_read(self, model: type, **hints: Any) -> str | None:
        return self._route(model)

    def db_for_write(self, model: type, **hints: Any) -> str | None:
        return self._route(model)

    def allow_relation(self, obj1: Any, obj2: Any, **hints: Any) -> bool:
        # default and test_mode are the same physical database (same host,
        # port and name; only search_path differs), so a Transaction row
        # routed to test_mode and a User row routed to default are always
        # a valid relation.
        return True

    def allow_migrate(
        self,
        db: str,
        app_label: str,
        model_name: str | None = None,
        **hints: Any,
    ) -> bool | None:
        if db == "default":
            return True
        if db == "test_mode":
            return model_name in TEST_MODE_MODEL_NAMES
        return None

    @staticmethod
    def _route(model: type) -> str | None:
        if not is_test_mode():
            return None
        if model._meta.model_name in TEST_MODE_MODEL_NAMES:
            return "test_mode"
        return None
```

## Post-Implementation Notes (CI hardening, 2026-09-11/14)

CI on the real Postgres service surfaced four bugs the plan's unit-level TDD steps
couldn't see:

1. **`reverse()` ambiguity.** Mounting `data_urlpatterns` a second time under
   `/api/v1/test/` with the same URL `name`s made `reverse("transactions_list")`
   resolve to the test route for every pre-existing test in the suite (~250
   failures). Fixed by namespacing the test mount:
   `include((data_urlpatterns, "test_mode"), namespace="test_mode")`.
2. **Shared migration bookkeeping.** `test_mode` and `default` are two Django
   connections to the *same* physical database; without its own
   `django_migrations` table, `test_mode` read `public.django_migrations` via
   search_path, saw every migration already applied, and never created its own
   tables - so every "test_mode" query silently fell through to `public`.
   `0013_create_test_mode_schema` now also clones an empty
   `test_mode.django_migrations`.
3. **Dangling and blocking foreign keys.** `allow_migrate` originally scoped
   `test_mode` to only the 8 activity models, but `Transaction` briefly had a
   migration-history-only FK to the retired `Season` model, and Postgres binds an
   unqualified FK reference at `CREATE TABLE` time via search_path - replaying
   history with `Season` excluded left a dangling reference. Widening the
   migration-time allow-list to include those legacy models (only for
   `allow_migrate`, never for runtime routing) fixes replay; a separate migration
   (`0014`) then drops the *cross-schema* FKs test_mode's activity tables end up
   with (to `public.commodities`/`users`/`harvest_seasons`), because Postgres
   refuses to `TRUNCATE` a table that's still referenced from another schema during
   any other test's plain (non-`transaction=True`) teardown - breaking unrelated
   tests project-wide, not just test_mode's own.
4. **Cross-connection visibility and cleanup.** `default` and `test_mode` are
   separate Postgres sessions to one database: a row inserted via `default` inside
   an ordinary rolled-back `django_db` test is invisible to `test_mode` until
   committed. Tests that create data on both need
   `pytest.mark.django_db(transaction=True, databases=["default", "test_mode"])`
   (real commits, `TransactionTestCase` semantics) - which in turn means nothing
   auto-rolls test_mode back between tests, so `tests/conftest.py` gained an
   autouse `reset_test_mode_activity` fixture deleting the four activity tables'
   `test_mode` rows before any test that declares `test_mode` in its `databases`.

Verified with the full suite green locally (669 passed, 408 snapshots) against a
fresh Postgres before pushing.

## Post-Implementation Notes (request-level bugs, 2026-09-17)

End-to-end tests beyond producer creation surfaced three more bugs:

1. **Accept and conversion returned 500.** `transaction.atomic()` without `using`
   only opens a transaction on `default`, so `Balance.objects.select_for_update()`
   on `test_mode` ran in autocommit and raised `TransactionManagementError`.
   `TestModeMiddleware` now runs the whole test-mode request inside
   `transaction.atomic(using="test_mode")` and rolls it back on any response with
   status >= 400, which matches the rollback the service-level blocks give on
   `default`.
2. **Real balances leaked into test mode.** Routing only the activity models left
   every query that starts from a reference model on `default`:
   `Commodity.objects.annotate_balances()` joined `public.balances`, so
   `/api/v1/test/commodities/groups/` showed the real totals. The router now sends
   every model to `test_mode` in test mode. Only the activity tables exist in the
   `test_mode` schema, so every other table still resolves to `public` through
   search_path, joins and subqueries included. `allow_migrate` is unchanged.
3. **Shared analytics cache.** `/analytics/user/` cached under the same key in both
   modes. Test mode now uses its own key.
